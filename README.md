# Иван & Алина — семейный центр

Рабочий семейный MVP для финансов, бюджетов, целей, планов и заметок. Интерфейс полностью на русском, адаптирован для MacBook, планшета и телефона.

## Что работает

- дашборд с балансом, доходами, расходами, чистым результатом и графиками;
- операции в USD, RUB и VND с автоматическим курсом и сохранённой суммой в базовой валюте;
- ежедневные автоматические курсы USD, RUB и VND с резервным источником;
- корректный пересчёт операций и отображаемых бюджетов при смене базовой валюты;
- отдельные остатки в долларах, рублях и донгах на главной странице;
- добавление, редактирование, подтверждение удаления, поиск, фильтры и сортировка операций;
- месячные лимиты по категориям, цветовые состояния и копирование прошлого месяца;
- финансовые цели с прогрессом, сроком, ответственным и пополнениями;
- общий планировщик в виде доски или списка, статусы, приоритеты и просрочка;
- общие и личные заметки, теги, закрепление, поиск и автосохранение черновика;
- светлая и тёмная темы;
- экспорт операций в CSV с UTF-8 BOM, полный JSON-бэкап и импорт с подтверждением;
- демоданные с быстрым восстановлением и удалением;
- локальный деморежим без внешних ключей;
- Supabase Auth, семейное приглашение, облачная синхронизация и безопасные RLS-политики.

## Локальный запуск

Нужен Node.js 22.13 или новее.

```bash
npm install
npm run dev
```

Откройте адрес, который покажет терминал (обычно `http://localhost:3000`). Без `.env` приложение сразу запустится с тестовыми данными. Они сохраняются в браузере этого устройства.

Проверки:

```bash
npm run lint
npm run typecheck
npm run test
```

Production build:

```bash
npm run build
```

## Подключение Supabase

1. Создайте бесплатный проект на [supabase.com](https://supabase.com).
2. Откройте `SQL Editor`, вставьте содержимое `supabase/migrations/202608110001_family_center.sql` и выполните запрос.
3. В `Authentication → Sign In / Providers` включите `Allow anonymous sign-ins`. Это позволяет Алине входить только по семейному коду, без email и пароля. Для создания семьи Иваном также оставьте включённым вход по email. Если `Confirm email` включён, задайте опубликованный адрес приложения в `Authentication → URL Configuration` как `Site URL` и добавьте этот же адрес в `Redirect URLs`.
4. В `Project Settings → API` скопируйте:
   - Project URL;
   - publishable key (или старый `anon` key для legacy-проекта).
5. Скопируйте `.env.example` в `.env.local` и заполните только эти два значения:

```env
NEXT_PUBLIC_SUPABASE_URL=https://PROJECT_REF.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=ваш_publishable_key
```

6. Перезапустите `npm run dev`.

Не используйте `secret` или `service_role` key в браузере и не коммитьте `.env.local`. Защита данных построена на Supabase Auth и Row Level Security, а publishable key предназначен для клиентского приложения.

## Создание аккаунтов Ивана и Алины

1. Иван открывает `Настройки → Supabase`, вводит email, пароль (минимум 8 символов), выбирает имя и нажимает `Создать семью`.
2. Приложение покажет восьмизначный код приглашения. Передайте его Алине безопасным способом.
3. Алина вводит только этот код и нажимает `Войти по коду`. Приложение создаёт защищённый анонимный сеанс автоматически — email, пароль и подтверждение почты не нужны.
4. Сеанс Алины сохраняется в её браузере. Ей не нужно повторно вводить код, пока она не выйдет из аккаунта и не очистит данные браузера.

Если Алина вышла, очистила браузер или впервые открыла установленную иконку сайта, примените миграцию `supabase/migrations/202608110003_allow_code_rejoin.sql`. После неё повторный ввод того же кода безопасно переносит место Алины на новый сеанс; последний вход Алины становится активным.

Чтобы старые бюджетные лимиты сохраняли исходную валюту и автоматически отображались в новой базовой валюте, один раз примените миграцию `supabase/migrations/202608110004_budget_currency.sql`. Существующие лимиты помечаются как USD, потому что это была исходная валюта приложения; новые лимиты запоминают валюту при создании.

Каждый аккаунт может состоять только в одной семье; в семейном пространстве может быть не больше двух участников. Оба видят общие данные. Личную заметку читает только её автор — это проверяется на уровне базы, а не только интерфейса.

## База данных и безопасность

Миграция создаёт таблицы:

- `families`, `family_members`, `family_settings`;
- `categories`, `transactions`, `budgets`;
- `financial_goals`, `family_tasks`, `notes`.

Функции `create_family_space` и `join_family_space` создают семью и проверяют код приглашения. RLS ограничивает все строки текущей семьёй. Для личных заметок действует дополнительное правило `author_id = auth.uid()`. Автор заметки защищён от подмены триггером. Финансовые суммы имеют проверки на положительные значения, валюты и статусы ограничены допустимыми значениями.

## Как устроен деморежим

Если Supabase не настроен, данные сохраняются в `localStorage`. Это удобно для ознакомления и полностью покрывает функции интерфейса, но не синхронизируется между устройствами. После подключения Supabase приложение автоматически сохраняет изменения в облако; в настройках также есть ручные кнопки `Загрузить` и `Сохранить`.

## Развёртывание

Проект использует Next.js App Router-совместимую среду Vinext и собирается в Cloudflare Worker. В Codex Sites достаточно выбрать публикацию сайта после успешной сборки. Для внешнего Cloudflare-проекта сначала задайте две переменные Supabase в настройках окружения хостинга, затем выполните production build и разверните Worker стандартным процессом Cloudflare.

Секреты не должны попадать в Git. Для клиентского приложения нужен только Supabase publishable key; старый `anon` key также поддерживается для совместимости. Административные `secret` и `service_role` keys не требуются.

## Структура ключевых файлов

- `app/family-center.tsx` — интерфейс и пользовательские сценарии;
- `app/globals.css` — дизайн-система и адаптивные состояния;
- `lib/demo-data.ts` — безопасные демонстрационные данные;
- `lib/cloud-data.ts` — чтение и запись данных Supabase;
- `lib/types.ts` — строгие TypeScript-модели;
- `supabase/migrations/202608110001_family_center.sql` — схема, функции и RLS;
- `supabase/migrations/202608110003_allow_code_rejoin.sql` — повторный вход Алины по коду;
- `supabase/migrations/202608110004_budget_currency.sql` — валюта бюджетных лимитов;
- `.env.example` — перечень нужных переменных окружения.

## Разумные идеи для второй версии

- необязательное автоматическое получение курсов из бесплатного источника;
- регулярные операции и напоминания;
- вложения к заметкам и целям через Supabase Storage;
- график прогноза остатка до конца месяца;
- история изменений и журнал резервных копий;
- PWA-установка и офлайн-очередь синхронизации.
